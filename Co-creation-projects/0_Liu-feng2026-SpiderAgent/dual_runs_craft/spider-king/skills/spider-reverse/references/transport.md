# Transport Playbook（传输层逆向）

## 定位传输差异

1. 对比浏览器成功请求与本地失败请求。
2. 确认 URL、Method、Headers、Body、Cookie 等业务参数基本一致。
3. 在业务参数一致的情况下，观察失败是否仍然存在。
4. 检查 HTTP 版本、TLS、代理、连接行为及客户端请求指纹等传输差异。
5. 记录成功与失败请求之间能够稳定复现的差异。

## 隔离传输变量

1. 每次只修改一个传输相关变量，并观察业务响应变化。
2. 分别测试 HTTP 版本、TLS 行为、代理、连接复用和客户端指纹等因素。
3. 找出导致请求成功或失败的最小差异。
4. 区分真正必要的传输约束与无关环境差异。
5. 记录能够稳定复现结果的最小传输条件。

## 本地恢复

1. 根据已确认的最小传输条件选择合适的 HTTP 客户端或传输实现。
2. 只恢复业务请求真正需要的 HTTP、TLS、连接或客户端指纹行为。
3. 保持请求逻辑与传输适配分离。
4. 不引入未经验证的额外传输配置。

## 验证

1. 使用恢复后的传输配置请求真实业务接口。
2. 确认获得有效业务数据，而不仅是 HTTP 请求成功。
3. 更换请求参数或重新建立连接后再次验证。
4. 重复执行，确认传输条件能够稳定复现。
