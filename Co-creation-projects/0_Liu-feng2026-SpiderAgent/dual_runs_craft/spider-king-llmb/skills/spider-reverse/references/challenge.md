# Challenge Playbook（验证逆向）

## 定位验证流程

1. 对比业务请求成功与失败时的请求链路。
2. 找出 Challenge、预检、遥测或其他验证请求。
3. 记录验证请求的 URL、Method、Headers、Body 和 Response。
4. 确认验证流程与业务请求之间的关系。

## 分析验证机制

1. 确认 Challenge 的输入、输出及触发条件。
2. 追踪验证参数的生成、修改和提交位置。
3. 确认验证成功后产生的状态或结果。
4. 找出这些结果如何影响后续业务请求。

## 本地恢复

1. 提取完成验证所需的最小请求和计算逻辑。
2. 按原始顺序恢复验证流程。
3. 保留完成验证真正需要的状态变化和依赖关系。

## 验证

1. 从新的初始状态执行完整验证流程。
2. 确认验证结果能够自动产生。
3. 使用验证结果请求真实业务接口，并以业务数据有效作为最终成功标准。
4. 重复执行，确认流程稳定可复现。
