# 重建路线分流（纯算 / AST 反混淆 / 补环境）

## 分流判定树

先看混淆（快速判据），再用 hook 后的依赖面确认（准确判据）：

```
跟栈拿到生成函数
├─ 代码可读、无混淆或轻混淆
│    └─ 只依赖入参与纯 JS 计算 → 纯算
├─ 混淆但呈结构化特征（字符串表数组、控制流平坦化、dead code 注入）
│    └─ AST 反混淆还原 → 回到纯算
└─ JSVMP/自定义字节码 VM，或逻辑深度耦合浏览器环境
     └─ 补环境（Node 局部执行，缺啥补啥）
```

准确判据的做法：hook 住生成函数，观察其执行实际触碰了哪些宿主对象——

- 只依赖入参、`Date`、`Math`、纯 JS 对象 → 纯算。
- 依赖 `document`/`canvas`/`navigator`/`screen`/`storage`/事件序列 → 补环境，或证明该依赖值恒定后直接抽取固定值。
- 字节码解释器循环 + 大查找表驱动 → JSVMP，以插桩分析为主，逆向指令集成本高时优先补环境。

混淆只是表象：有的重混淆反混淆后照样纯算，有的无混淆但环境依赖重仍要补环境。两个判据冲突时以依赖面为准。

## 纯算路线

1. 固定样本对拍：从浏览器运行时保存至少一组已知输入 → 输出。
2. 识别算法：不因函数名、输出长度或格式相似就假定为标准算法；注意魔改摘要（改初始值/常量/轮数）、自定义盐、uint32 截断、`ROTL` 边界、逐字节打包掩码。
3. 用 Python（或 Node）重写，固定样本全部通过后才接入重放。
4. 用新鲜动态输入生成后发起真实请求验证。

## AST 反混淆路线

1. 特征识别：obfuscator.io 家族（字符串数组 + 解码函数、switch 控制流平坦化、字面量与成员表达式混淆、self-defending）。
2. 用 Babel AST 做结构化还原：字符串内联、控制流还原、常量折叠、成员表达式简化。非执行式处理优先，不先 beautify 硬读。
3. 还原后的代码回到纯算路线处理。
4. 反混淆只做结构还原，不做行为推断；还原产物同样要固定样本对拍。

## 补环境路线

1. 执行细节走官方 `mcp-js-reverse-playbook`（代理 env log + first divergence + 最小因果单元），本文件只负责路由判断。
2. 边界约束：只补该函数真实依赖的环境，不做整页模拟；最终形态是 Python 拥有全部真实 HTTP，Node 只作为最小本地 helper，不依赖实时浏览器页面。
3. 常见检测点：`navigator.webdriver`、canvas 指纹、`storage`、事件时序、屏幕与字体枚举。逐项按 first divergence 补齐，不做预防性大而全补环境。
4. 补环境产物同样要固定样本对拍，且脱离浏览器可独立运行。

## 共同验收

- 固定输入输出对拍通过。
- 新鲜动态输入下真实业务请求成功且返回有效数据。
- helper 自包含，可被 Python 侧稳定调用，不携带运行时前置依赖。
