# Session Playbook（会话逆向）

## 定位会话建立流程

1. 找出登录、初始化、配对等建立业务会话的请求。
2. 确认关键 Cookie、Token、Key、counter 等状态从哪里产生。
3. 明确建立可用业务会话所需的最小步骤。

## 分析状态依赖

1. 追踪状态的生成、写入和消费位置。
2. 明确各状态之间的依赖关系。
3. 确认状态是否与时间、设备、用户或其他上下文绑定。
4. 区分身份会话与业务上下文，登录成功不代表业务会话已经完整建立。
5. 以最终实际发出的 Cookie、Headers 等线上状态为准，不只依赖本地存储状态。

## 分析状态流转

1. 找出状态的更新、刷新和失效条件。
2. 确认 counter、heartbeat、请求顺序等状态约束。
3. 明确状态更新的先后顺序和触发条件。

## 恢复会话

1. 按依赖顺序建立并维护业务会话。
2. 自动生成、更新和传递必要状态。
3. 动态状态不得硬编码。

## 验证

从新的初始状态重新建立会话，并确认能够持续获得有效业务数据。
