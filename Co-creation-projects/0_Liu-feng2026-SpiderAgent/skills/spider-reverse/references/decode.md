# Decode Playbook（响应解码）

## 定位编码/加密边界

1. 保存业务接口返回的原始 Response。
2. 对比原始响应与最终业务数据。
3. 判断数据是否经过编码、压缩、加密、序列化或其他转换。
4. 定位原始 Response 第一次被处理的位置。
5. 确认处理前后的输入与输出。

## 追踪解码流程

1. 从原始 Response 的处理入口沿调用链追踪。
2. 记录每一步转换的输入、输出及执行顺序。
3. 确认 Key、IV、字典、配置或其他依赖的来源。
4. 区分标准编码/算法与业务自定义转换。
5. 确认最终哪一步产生可解析的业务数据。

## 本地重建

1. 提取恢复业务数据所需的最小解码链。
2. 按原始顺序重建各层转换。
3. 保留解码真正需要的算法、参数和依赖。

## 验证

1. 保存一组原始 Response 与正确业务数据作为固定样本。
2. 使用本地解码流程处理固定样本，并确认结果一致。
3. 使用新的真实 Response 再次验证。
4. 确认能够稳定得到有效业务数据。
