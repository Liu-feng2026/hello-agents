# Signer Playbook（签名逆向）

## 定位签名字段

1. 捕获多次相同业务请求。
2. 对比 URL、Headers、Body 和 Cookie。
3. 区分固定字段与动态字段。
4. 修改或移除可疑字段，观察业务响应变化。
5. 确认哪些字段真正参与请求校验。

优先关注随请求变化且会影响业务结果的字段。

## 追踪签名生成位置

1. 定位签名字段写入 URL、Headers 或 Body 的位置。
2. 找到生成该字段的函数或调用链，并确认是否存在多个 writer（写入者）。
3. 继续追踪 timestamp、nonce、请求参数、Cookie 等输入来源。
4. 确认实际的数据处理和算法流程，不因算法名称、输出长度或格式相似就假定为标准算法。
5. 记录完整的输入 → 处理 → 输出关系。

优先追踪“谁把值写进请求”，不要直接从大量混淆代码中搜索算法。

## 本地重建与验证

1. 保存一组已知输入和签名输出作为固定样本。
2. 提取签名所需的最小逻辑和依赖。
3. 使用固定样本验证本地结果与原始结果一致。
4. 使用新的动态输入生成签名，并验证真实业务请求。
